# ShuttleDuel 🏸⚔️

羽球社的雙打排位配對系統。社員到場報到後排隊，系統依實力配對對手、分配場地，並透過 Discord 通知每個人輪到自己上場。

[English](README.md) · **繁體中文**

> **開發狀態：** 核心邏輯（資料庫、積分、配對、比賽流程、通知佇列、中英訊息）已完成並有測試；Discord Bot 與網頁後台開發中。

## 設計重點

- **雙打、先來先上。** 照報到順序配對，只有實力差距過大時才會跳過；等越久，允許的差距越寬，不會有人永遠卡住。
- **Elo 積分。** 贏加分、輸扣分，爆冷變動更大。新手前 10 場變動較大，積分收斂比較快。
- **學期制。** 積分以學期為單位。每學期社長開新學期（例如 `1151`）、加入新成員，舊學期的紀錄完整封存。
- **Discord 通知。** 對決邀請、準備按鈕、回報比分都走私訊，頻道保持安靜。
- **中英雙語。** 所有給球員看的訊息都有英文與繁體中文。
- **簡單部署。** Python + SQLite，一個程序就能跑，不需要另外架資料庫。

## 專案結構

| 檔案 | 說明 |
|---|---|
| `rating.py` | Elo 積分計算 |
| `matching.py` | 配對演算法（純函式，不依賴資料庫或 Discord） |
| `service.py` | 比賽流程：排隊、場地、準備逾時、回報比分、社長操作、通知佇列。Bot 與網頁都只呼叫這一層 |
| `messages.py` | 所有給球員看的文字（English + 繁體中文） |
| `db.py` | 資料庫連線、遷移、交易、學期管理 |
| `migrations/` | 資料表定義，依編號依序執行 |
| `test_*.py` | 測試 |

## 執行測試

需要 Python 3.10 以上，不需要安裝任何套件：

```
python test_db.py
python test_core.py
python test_service.py
python test_messages.py
```

## 比賽流程

```
排隊 → 配對成功 → [下一場預告] → 場地空出 → 準備（3 分鐘）→ 比賽中 → 回報 → 對方確認 → 結算積分
```

- **下一場預告：** 場地還在打的時候，最多預告 2 場，讓下一組先走到場邊，場地不會閒置。
- **準備逾時：** 有人沒按準備，該場作廢。按了準備的人保留原本的排隊順位、重新配對；沒按的人排到隊尾。
- **回報：** 任一人回報比分（21 分制、領先 2 分、30 分封頂），對方隊伍任一人確認後才計分。對方不同意會退回重報並通知社長，社長可直接裁決。
- **先回報才能再排隊：** 上一場還沒回報結果的人不能進入下一輪。
- **社長 / 管理員：** 可下架比賽（不計分）、裁決比分、調整場地數與積分（會留下紀錄）、移出排隊、結束社課。

## Bot 與網頁怎麼串接

兩者是獨立的程序，共用同一個 SQLite 資料庫，彼此不直接呼叫。

1. 任何動作都透過 `service.py`，通知不會直接發送，而是寫進 `notifications` 資料表。
2. Bot 每隔幾秒呼叫 `service.pending_notifications()` 取出通知、用 `messages.render()` 產生文字並私訊，成功後呼叫 `mark_sent()`；失敗則呼叫 `mark_failed()`，失敗次數過多會放棄。
3. Bot 同時每隔幾秒呼叫 `service.tick()`，處理準備逾時與場地補位。
4. 即使 Bot 暫時重啟，未發送的通知仍保留在資料庫，不會遺失。

## 每學期怎麼換人

1. 社長用學期代號開新學期（例如 `1151` = 民國 115 年第 1 學期）。
2. 舊學期自動封存，進行中的社課也會結束。
3. 社長把這學期的成員加進來，可以順便指定初始積分（例如校隊 1300、菜鳥 800，其他預設 1000）。
4. 沒有被加進新學期的人不會出現在這學期的排隊與排行榜，但舊紀錄都還在。

## 調整規則

在 `matching.py` 開頭：

| 參數 | 預設 | 說明 |
|---|---|---|
| `BASE_WINDOW` | 150 | 一開始允許的分數差 |
| `WINDOW_PER_MIN` | 50 | 每多等 1 分鐘放寬多少 |
| `UNLIMITED_AFTER_MIN` | 10 | 等超過幾分鐘就不限制 |

在 `service.py` 開頭：`READY_TIMEOUT`（按準備的秒數）、`UPCOMING_LIMIT`（預告幾場下一場）、`WIN_POINTS` 與 `MAX_POINTS`（比分規則）。在 `rating.py` 開頭可以調整 K 值與幾場以內算新手。

## 修改資料表

不要修改舊的 migration 檔。新增下一個編號的檔案（例如 `003_xxx.sql`），下次啟動時會自動套用。

## 隱私與安全

- 資料庫檔（`*.db`）裡有社員的暱稱與 Discord ID，請不要提交到 GitHub（已列在 `.gitignore`）。
- Bot Token 放在 `.env`，不要提交。萬一外洩，立刻到 Discord 開發者後台重新產生。
- 每個社團自己建立 Discord Bot、自己部署一份，彼此資料不互通。
